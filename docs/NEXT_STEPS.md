# contE — 次期開発引き継ぎ資料

更新日：2026-09-13。初期実装 `8b928b0` を基準とする。これは今後の実装計画であり、未実装機能の完成報告ではない。

## 1. 目的と判断基準

「絵コンテを考える速度をソフトが邪魔しないこと」を最優先する。最終目標は **描く → Panel追加 → 尺調整 → Camera設定 → 音配置 → 再生 → 紙コンテ / PDF / Animatic出力** の一貫した制作環境。

機能数より、操作数・視線移動・待ち時間・誤操作・復旧の確実さで判断する。一度に全機能を実装せず、下記の段階ごとに実装と検証を完結させる。

## 4. 次に行う順番と完了条件

### P0 — 保存・復旧とデータ基盤（次回の主対象）

1. `ProjectRepository` をUIから分離し、手動保存・自動保存・読み込み・復旧を一か所に集める。
2. ブラウザ段階ではIndexedDBにプロジェクトと素材を保持。変更からの遅延保存と保存状態表示を設ける。保存失敗を成功表示しない。
3. 起動時に復旧候補の日時/名前を見せ、復旧または破棄を選べるようにする。壊れた保存で正常な直前データを上書きしない。
4. `Asset` IDと画像/音声バイナリを分離する。履歴に巨大な素材データを複製しない。形式更新が必要ならv1→v2 Migrationを先に作る。
5. 編集コマンド単位の履歴と選択状態復元を点検する。無効/無変更操作でUndo段数を消費しないようにする。

完了条件：保存後の再起動で絵・尺・台詞・Cameraが一致。編集中の強制終了から正常な最終保存へ復旧できる。容量不足/不正JSON/未知Versionで元データを失わない。旧v1 fixtureの読込テストが通る。

次回はまずこのP0を完了させる。音声やレイヤーを同時に作り切ろうとしない。

### P1 — 描画とPanel操作を実用水準へ

- 画像ファイルをPanelへ取り込む。縦横比、透明度、巨大画像の縮小/元画像保持を明確にする。
- ブラシサイズ、消しゴム、筆圧、Canvasズーム/パンをDrawing Adapterに実装。描画と尺変更の履歴を一貫させる。
- Shift範囲選択、ドラッグ順序変更、Scene/Shot名編集、選択Panelへの自動スクロール。
- 左ツリー・中央Canvas/Strip・右Inspector・下Timelineをリサイズ可能にし、ペイン幅を保存する。低頻度項目はInspectorタブ/コンテキストメニューへ。

完了条件：10 Panelのラフを描き、複製・修正・尺変更までCanvasとTimelineを行き来するだけで完成できる。ドラッグ中断時に描画/順序が壊れない。削除/移動/描画をUndoして元の絵と選択位置へ戻れる。

### P2 — Timeline EngineとCamera Track

- `src/app.js`内のTimeline計算とDOM操作を分け、Timeline Engineに範囲/スナップ/リップル規則を集約。
- fps基準の目盛、選択範囲、再生ヘッド追従、カーソルまたは再生ヘッドを基準とするZoom。
- CameraキーをPanel内の任意時刻で追加・移動・削除。尺変更時のキーの扱いを仕様化し、紙面/再生/動画で同じ補間関数を使う。
- Pan/Tilt/Zoom/Rotation/Holdを開始/終了枠、矢印、軌道、注記で編集・確認できるようにする。

完了条件：500 Panelでスクロール・ズーム・境界スクラブが破綻しない。正確なフレーム境界で次Panelへ移る。尺変更/Shot分割/Undoの前後でCameraキーと映像の整合が保たれる。

### P3 — 音配置・波形・同期再生

- Dialogue/SE/BGMの音声クリップに開始位置・素材内オフセット・長さ・ゲインを持たせる。台詞テキストと音声クリップは別データとして関連づける。
- デコードと波形計算をキャッシュし、UIスレッドで毎回波形を作り直さない。
- Audio Engineの時計を基準にPlayback Engineと同期。seek、停止、再開、終了時の音の残留を防ぐ。
- 紙コンテの音注記は明示的な紐づけ/時間重なり規則から取得する。

完了条件：BGMとSEを置き、尺変更後の位置ルールが一貫する。繰り返しseekして二重再生しない。長時間再生の同期誤差を測定して記録する。音素材が見つからない場合に修復できる。

### P4 — 紙コンテを本番出力へ

- 用紙サイズ/向き、列の順番/個別幅、表示項目、ヘッダー/フッターを設定モデル化し、プロジェクトへ保存する。
- 長文は切り捨てず、行高調整または継続行/ページで読めるようにする。
- Paper RendererとExporterを分離。プレビューの全ページ同期走査をなくし、進捗/キャンセルを追加する。
- Camera TrackからPan矢印、Tilt上下矢印、Zoom開始/終了枠、移動軌道/注記、HOLDを一貫生成。
- PNGは連番ZIP等でまとめて取得できるようにする。PDFの日本語・改ページ・余白を検証する。

完了条件：日本語長文、特殊記号、回転/Zoom、1/4/8コマ、複数ページを見比べて欠落がない。500 Panelの出力中にUIが固まらず、キャンセル可能。WindowsのPDF保存と実印刷は別々に確認する。

### P5 — Animatic出力とWindowsデスクトップ化

- 出力fps/解像度を指定し、映像と音声を同じフレーム評価関数でレンダリングする。
- 出力中断/再試行、一時ファイル削除、出力失敗時の素材保護を実装する。
- Windowsのペン入力、ファイル上書き、音声、メモリ使用量を比較してからネイティブシェルを選定。初めから特定フレームワークを前提にしない。
- コーデック/動画エンコーダ/追加ライブラリのライセンス、再配布条件、保守、容量を調べ、採用理由を記録する。

完了条件：3分の音付きAnimaticで尺/Camera/音位置がプレビューと一致する。通常権限のWindowsでインストール・起動・保存・出力が通る。

## 5. 責務分離の到達点

| 責務 | 現状 | 次の分離先/責任 |
|---|---|---|
| Project Model | model.js | schema・validation・migration・asset参照 |
| Project Repository | app.jsの保存処理 | 永続化・復旧・素材読み書き |
| Timeline Engine | model.js / app.js | フレーム区間・編集規則・スナップ |
| Playback Engine | playback.js / app.js | 時計・seek・表示更新、後に音声同期 |
| Drawing Engine Adapter | drawing.js | 描画・消去・入力変換、表示とデータの分離 |
| Audio Engine | 未実装 | decode・waveform cache・schedule・mix |
| Camera Animation | model.js / paper.js | キー評価・補間・軌道記述の共有 |
| Paper Storyboard Renderer | paper.js | レイアウト・改ページ・文字計測・Camera表記 |
| Exporter | paper.js / app.js | PDF・PNG・動画の生成と進捗/中断 |
| UI | app.js / index.html / style.css | 状態表示・入力・ペイン管理 |

分離は各フェーズに必要な箇所から行う。未使用の抽象クラスを大量追加しない。

## 6. 検証と性能基準

既存コマンド：`npm test`、`npm run build`、`npm run bench`、任意環境で`npm run test:browser`。詳しい初期測定は[DEVELOPMENT.md](DEVELOPMENT.md)。モデルの0.12msという数値をUI全体の応答時間として報告しない。

| 評価 | 次回以降の方法 |
|---|---|
| Panel/Shot作成、尺変更 | 代表操作のクリック/キー操作数を記録 |
| Scene移動 | 5Scene×100Panelで選択から描画完了を測定 |
| 100/500 Panel | 空Panel・線画多め・実画像/音ありのfixtureを分ける |
| 再生開始 | コマンドから最初の表示/音まで。準備済み/初回を分ける |
| スクロール/Zoom | 入力から描画完了の中央値/p95とドロップフレーム |
| 保存 | JSON化・素材書込み・保存完了を分け、サイズも記録 |
| Undo/Redo | 描画/尺/キー/削除/分割/統合の混合操作で往復一致 |
| 紙出力 | 操作数、初回プレビュー時間、全出力時間、最大メモリ |

目標値は実機基準で設定する。暫定目標は通常編集のp95を50ms以下、準備済み再生開始を100ms以下とする（達成保証ではない）。測定環境、サンプル数、素材条件、待機した描画フレーム数を必ず併記する。

各サイクルの終了時に「変更内容 / 変更理由 / 改善効果 / 残存問題 / 次に最も価値の高い改善」を記録する。テスト失敗や未検証事項を完成扱いしない。

## 7. 次の担当者への着手手順

1. この資料、README、ROADMAP、DEVELOPMENT、最新のmainと変更履歴を読む。
2. `npm test`と`npm run build`で開始時点を確認。現在のUIを操作して保存/Undoの不便を再現する。
3. P0の自動保存・復旧・ProjectRepositoryから着手し、失敗時のデータ保護を先にテストする。
4. P0の完了条件を満たしたらP1へ進む。時間が残る場合もフェーズを飛び越えて機能を増やさない。
5. 実装・測定・操作確認を行い、この資料の状態表と開発ノートを更新する。
