## Bundle読み込みの原子性

既存Storageのbatchを利用し、全素材のハッシュと既存IDの競合を確認してから一つのトランザクションで追加する。素材操作とGCはRepositoryの同じキューを通す。Projectの置き換えはトランザクション完了後に同期的に実行する。

容量不足・途中書き込み失敗・入力不正では追加全体を取り消す。読み込み中にSession、revision、入力下書きが変わった場合は置き換えを中止する。完了直後に変更を検知した場合も、このimportで追加した素材だけを削除し、既存の共有素材には触れない。別の永続stagingストアは追加していない。

## 検証コマンドと境界

- `npm test`：既存テストと保存・import・IMEの回帰テスト。
- `npm run build`：静的配布物の生成。
- `npm run test:browser`：既存の制作・再生・出力・復旧シナリオ。
- `npm run test:ux`：今回の操作シナリオ。

ブラウザ検証はGitHub ActionsのChromiumを使う。Windows Ink実機、タッチペンの物理遅延、Safari固有挙動、512MiB付近の常駐メモリは未実測。容量上限はメモリ性能の保証値ではない。大規模実測とストリーミング出力は引き続きNEXT_PLANの対象。
